# دليل التشغيل والاختبار في Smart Plant

## الفكرة العامة

Smart Plant هو نظام مراقبة وتحكم محلي للري الذكي. يقرأ التطبيق بيانات Arduino عبر USB/Serial، أو يستقبل Telemetry مستمرة من أداة مستقلة، أو يشغّل محاكاة معزولة لأغراض الاختبار. كل قراءة تحمل مصدراً واضحاً: `ARDUINO_SERIAL` أو `DEVICE_TOOL` أو `SIMULATION`. لا تستخدم شاشة Arduino / Live بيانات المحاكاة كبديل عند فقد المصدر الحقيقي.

## مسارات البيانات

```text
حساس رطوبة التربة → Arduino Uno / A0 → USB Serial 115200
                                   └→ Smart Plant validation → ARDUINO_SERIAL

Smart Plant Telemetry Tool GUI → /api/tool/inject + /api/tool/heartbeat
                              └→ Smart Plant validation → DEVICE_TOOL

Smart Plant / Simulation → دورة جفاف ثم رطوبة ثم انخفاض
                         └→ Simulation view only → SIMULATION

المصدر المقبول → تحقق من النطاق والوقت والهوية → منطق Rain Guard والتحكم
               └→ سجل الأحداث + واجهة المراقبة + ملف JSON المحلي
```

## تشغيل النظام الرئيسي

شغّل ملف **Smart Plant System.exe**. يفتح التطبيق خادماً محلياً على المنفذ الأساسي `3177`، وينتقل تلقائياً إلى منفذ متاح ضمن المجال المحلي إذا كان المنفذ مستخدماً. يبحث التطبيق عن Arduino تلقائياً، ويمكن تحديد منفذ مخصص باستخدام متغير البيئة `SMART_PLANT_COM_PORT`. الاتصال التسلسلي مضبوط على `115200 baud`.

وصّل `AO` من حساس الرطوبة إلى `A0` في Arduino، و`VCC` إلى `5V`، و`GND` إلى `GND`. ارفع الكود الموجود في `hardware/arduino_soil_sensor/arduino_soil_sensor.ino`، ثم أغلق Serial Monitor في Arduino IDE قبل تشغيل التطبيق. لا يحتاج المستخدم إلى تشغيل Node أو Python عند استخدام ملف EXE.

## واجهة المحاكاة

افتح **المحاكاة** واضغط **ابدأ المحاكاة**. تبدأ الدورة بقيمة جافة مرتفعة، ثم تنتقل تدريجياً إلى رطوبة متوسطة وعالية، ثم تنخفض وتعيد الدورة كل ثانية. تعرض الشاشة القراءة السابقة والحالية، الرسم البياني، المصدر `SIMULATION`، الحالة `RUNNING`، وقرار المضخة الافتراضي.

اضغط **إيقاف المحاكاة** لإيقاف توليد القراءات الجديدة دون حذف الرسم أو سجل الأحداث. زر **إعادة الضبط** يعيد حالة العرض فقط؛ السجل التدقيقي السابق يبقى محفوظاً. هذه الدورة لا تمثل حساساً حقيقياً ولا ترسل بيانات إلى مسار Arduino / Live.

## واجهة Arduino / Live

تعرض الشاشة آخر قراءة حديثة وصالحة من `ARDUINO_SERIAL` أو `DEVICE_TOOL` فقط، وتوضح القراءة السابقة، القراءة الحالية، وقت آخر قراءة، القيمة الخام، معرّف الجهاز، الرسم البياني، المنفذ، وحالة الاتصال. عند عدم وجود قراءة صالحة تظهر رسالة **قد لا تتوفر بيانات حالياً** بدلاً من استخدام المحاكاة.

تُحدّث الشاشة تلقائياً كل ثانية، وتلتقط حتى أصغر تغير في القراءة الجديدة. استخدم **تحديث وإعادة محاولة** لإعادة فحص API والاتصال عند الحاجة. إذا كان المصدر `DEVICE_TOOL` تظهر حالة heartbeat ووقت آخر نبضة. عند إيقاف الأداة أو تجاوز المهلة تظهر حالة انقطاع واضحة مع الاحتفاظ بآخر قراءة معلّمة بأنها غير متصلة.

ألوان الحالات هي: الأحمر للجفاف المرتفع أو الرطوبة العالية، والأخضر للرطوبة المتوسطة المستقرة. يظل المصدر مكتوباً صراحة ولا يعرض `DEVICE_TOOL` على أنه Arduino.

## التحكم بالمضخة

توجد أزرار التحكم في شاشة المحاكاة وشاشة Arduino / Live:

| الوضع | السلوك |
|---|---|
| `FORCED ON` | يشغّل المضخة ويمنع الأتمتة من إيقافها بسبب القراءات الجديدة. |
| `FORCED OFF` | يوقف المضخة ويمنع الأتمتة من تشغيلها بسبب القراءات الجديدة. |
| `AUTO` | يعيد التقييم فوراً اعتماداً على آخر قراءة صالحة، ويسجل مصدر الأمر والوضع. |

يسجل كل تغيير في `سجل_الأحداث.json` مع الوقت، المصدر، النوع، السبب، حالة المضخة، والوضع. فقدان الاتصال أو القراءة غير الصالحة لا يشغّلان المضخة تلقائياً.

## واجهة حالة الطقس وRain Guard

افتح **حالة الطقس** واكتب اسم مدينة ثم اضغط **بحث وتحديث**. تستخدم الواجهة بيانات Open-Meteo العامة لعرض الحالة الحالية، الحرارة، الرطوبة، ملخص اليوم، وتوقعات سبعة أيام، مع تمييز ممطر/غائم/مشمس بأيقونة ولون.

لا تحفظ الواجهة حالة طقس تجريبية موثوقة. إذا تعذر الوصول إلى المصدر تظهر رسالة عدم توفر البيانات، ولا يُبنى قرار نهائي على طقس وهمي. عند وصول قراءة جفاف في وضع `AUTO`، إذا كانت حالة الطقس الموثوقة ممطرة يتم تسجيل **تم تجاهل الري بسبب وجود المطر** وتبقى المضخة متوقفة. إذا كانت مشمسة أو لا توجد حالة مطر موثوقة، يبدأ الري وتسجل قاعدة الجفاف. وعند تجاوز حد الإيقاف بعد تحسن الرطوبة تتوقف المضخة ويسجل السبب.

## أداة Smart Plant Telemetry Tool

شغّل **Smart Plant Telemetry Tool.exe** بشكل مستقل. لا تحتاج الأداة إلى Node أو Python مثبتين. أدخل عنوان النظام والمنفذ، ثم اضغط **إعادة الاتصال واكتشاف Port تلقائياً**. يبدأ الاكتشاف من `3177` ويجرب المنافذ التالية محلياً عند الحاجة.

اختر `FIXED` لإرسال القيمة اليدوية الحالية، أو `RANDOM` لإجراء تغيرات عشوائية مقصودة داخل الأداة. يمكن تعديل القيمة بالمنزلق أو بإدخال الرقم، وتحديد معدل الإرسال حتى كل ثانية. عند الضغط على **بدء الإرسال** ترسل الأداة JSON متوافقاً مع البروتوكول الحالي:

```json
{"value":42.5,"raw":612,"ts":"2026-08-28T10:15:00.000Z","deviceId":"spoof-tool-01","calibration":"tool-gui-v2","source":"DEVICE_TOOL"}
```

ترسل الأداة القراءة والـ heartbeat في مسارين مستقلين. تعرض حالة الاتصال، وقت آخر إرسال، وقت آخر heartbeat، عدد الرسائل الناجحة، وعدد الأخطاء. عند فشل الاتصال تعيد المحاولة تلقائياً دون استعمال بيانات المحاكاة. عند الضغط على **إيقاف الإرسال** تتوقف الرسائل الجديدة، ثم يظهر الانقطاع في النظام بعد انتهاء مهلة heartbeat.

## واجهة الاختبار

افتح **صحة البيانات والتدفق** واضغط **ابدأ الاختبارات**. يمكن إعادة الاختبار في كل مرة بالضغط على الزر نفسه؛ تُمسح النتيجة السابقة أثناء بدء الفحص ثم تُعرض النتيجة الجديدة بعد وصول الردود الفعلية. الفحوصات المنفصلة هي: صيغة JSON، نطاق الرطوبة `0–100%`، مصدر القراءة، مسار المصدر إلى الواجهة ومنطق القرار، اتصال Arduino، أكثر من قراءة متتابعة، heartbeat أداة Telemetry، وعدم استخدام fallback من المحاكاة.

إذا كانت أداة Telemetry تعمل، يظهر المصدر `DEVICE_TOOL` بوضوح ويصدر النظام إشعاراً بأن البيانات غير موثوقة وقد تكون متلاعباً بها. أما إذا كان المصدر `ARDUINO_SERIAL` واتصال Arduino فعالاً، فيصدر النظام إشعاراً بأن البيانات سليمة وموثوقة. إذا كان Arduino مفصولاً تظهر صراحة نتيجة عدم توفر الاتصال، ولا تستبدل الواجهة ذلك بنجاح زائف أو قراءة محاكاة.

## سجل التنبيهات والتدقيق

تعرض شاشة **سجل التنبيهات** الأحداث السابقة مع مرشحات مستقلة للمحاكاة، Arduino / Live، Telemetry، النظام، والطقس. يشمل كل حدث وقتاً، مصدراً، نوعاً، سبباً، حالة المضخة، والوضع وقت الحدث. تتضمن الأنواع بدء وإيقاف المحاكاة، الجفاف، الرطوبة العالية، بدء الري، إيقافه، Rain Guard، أوضاع التحكم اليدوي، فقد الاتصال، إعادة الاتصال، ورفض الرسائل غير الصالحة.

## كود Arduino والتعديل المطلوب

أصبحت القراءة والتحديث كل ثانية، مع متوسط عشر قراءات، والمعايرة عبر `DRY_RAW` و`WET_RAW`، والإرسال بسرعة `115200 baud`. أضيف فقط مسار ريليه المضخة على `D7` وبروتوكول `PUMP_ON`/`PUMP_OFF` مع إيقاف أمان عند فقد الأوامر. الكود الحالي يرسل `ts_ms` من `millis()`؛ يتعامل خادم Smart Plant معه كزمن وصول حديث مع الحفاظ على التحقق من القراءات التي تحمل ISO timestamp. يجب رفع نسخة Arduino المعدلة إذا أُريد تشغيل المضخة فعليًا.

## الاختبارات العملية قبل التسليم

نفّذ بدء وإيقاف المحاكاة، وتحقق من دورة الجفاف والرطوبة والانخفاض. ثم اختبر Arduino متصلاً ومفصولاً، وجرّب `FORCED_ON` و`FORCED_OFF` و`AUTO`. بعد ذلك شغّل Telemetry بمعدل ثانية، راقب `DEVICE_TOOL` والـ heartbeat، افصل الأداة ثم أعد الاتصال. اختبر الطقس الممطر والشمسـي، ثم راجع فلاتر السجل ومصادر الأحداث. لا تُعرض أي نتيجة نجاح إلا بعد تنفيذ الاختبار فعلياً من الواجهة.

> ملاحظة: شاشة الطقس تعتمد على توفر الإنترنت ومصدر Open-Meteo. أما Arduino وTelemetry وقرارات المضخة فتعمل محلياً عبر خادم Smart Plant.


## ربط المضخة المادي

أضيف إلى كود Arduino مسار ريليه آمن على المنفذ الرقمي D7. أوامر التطبيق `PUMP_ON` و`PUMP_OFF` تُرسل عبر نفس Serial بسرعة 115200، ويعيد Arduino تأكيداً داخلياً. عند انقطاع أوامر التطبيق لمدة 15 ثانية تُطفأ المضخة تلقائياً. استخدم ريليه أو MOSFET مناسباً، ومصدر تغذية منفصلاً للمضخة، واشترك في GND فقط عند الحاجة؛ لا توصل مضخة أو جهد الشبكة مباشرة بمخرج Arduino. إذا كان الريليه Active-Low غيّر `PUMP_ACTIVE_HIGH` إلى `false` قبل رفع الكود.

يظل مسار Telemetry الخلفي متاحاً للتغذية والاختبار، لكن عناصره لا تظهر في الواجهة التشغيلية العامة؛ أما فحوصات صحة البيانات فتحتفظ بالتمييز الداخلي اللازم للتدقيق والاختبار.
